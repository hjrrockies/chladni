# Overview
`chladni` is a Python project to rebuild my solver for Laplacian eigenvalues of planar domains (`lappy`) from the ground-up, based on the lessons learned while building the original. The core features of `chladni`:

1. Geometry: Boundary curves of various types are supported. Boundary curves are used to define Domain objects. All of the geometric objects have adaptive methods for efficient point sampling, corner detection, area/perimeter/diameter computation, simplicity/non-degenercy enforcement, etc. Boundary curves come with attached boundary conditions, which are observed by the eigensolver.
2. Particular solution families: So-called particular solutions of the Helmholtz equation are defined and available for fast, vectorized evaluation. These include corner-adapted fractional-order "Fourier-Bessel" functions, monopole real-valued fundamental solutions, multiple fundamental solutions, and plane waves. The basis functions can have their derivatives evaluated as well.
3. GSVD-based MPS eigensolver: Uses a regularized form of the GSVD formulation of the method of particular solutions to compute the eigenvalues of the domain. Computes orthonormal sets of eigenfunctions using Rellich-identity boundary integrals, approximated with quadrature.

# Design principles
- User-specified working precision: Everything approximate within `chladni` is attached to a user-specified value `prec`, which is the relative precision expected for the computed quantity. Specific tolerances are derived from `prec`, which is equal to 1e-8 by default, but can go as low as 1e-15. `chladni` aims to provide 8 digits of precision, and should deliver more when requested.
- Vectorization: Avoid explicit loops, and use NumPy vectorization whenever possible, unless there's a good reason not to.
- Lazy evaluation, rather than eager
- Parallelization: Embarassingly-parallel computations should be parallelized with threads, when possible.
- Black-box functionality: A user should be able to supply purely geometric information (i.e. a Domain object), construct an Eigenproblem object from that domain, and then solve for eigenvalues without *needing* to explicitly construct or tune a MPS instance (basis, collocation points, etc). While those features are exposed, the black-box path should be reliable for non-pathological domains and reasonable precision (at least 1e-8, better when requested).
- Built for use as eigensolver inside spectral shape optimization or spectral shape inverse problems: `chladni` can and should handle "bespoke" domains, but its real deep purpose is to be the black-box solver for a larger shape optimization/shape inverse problem that iterates through multiple algorithmically-generated domains.
- Pythonic functionality: standard Pythonic functionality, such as operator overloading, should be included to provide "syntatic sugar" for the end-user.
- Test-driven development: Once an API is established, unit tests should be built before designing the implementation. Tests should be based in ground-truth, whenever possible. As `chladni` becomes more robust, it can be used to generate reference values that work as ground truth for new features or fine-tuning adjustments.
- Polygons first, but don't unnecessarily exclude curved boundary domains: `chladni` is trying to be a black-box-ready solver for domains with corner singularities, for which polygons are the prime example. The code should be built to *crush* the polygonal eigenproblem whenever feasible. However, `chaldni` should also be able to handle domains with curved boundary, hopefully just as well as it does for polygons (eventually). To keep the design process modular and ordered, the polygon case should be handled first, unless the general case is simple enough to subsume the polygon case right away.
